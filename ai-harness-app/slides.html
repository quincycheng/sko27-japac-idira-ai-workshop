Set expectation: by the end you'll know exactly what an "agent" is, because we'll have built one in front of you with no framework. Everything is live against Vertex. If something breaks, that's the honest reality of agents.

The claim

An agent is a model in a loop that can call tools.

That's it. Claude Code, Cursor, your SOC copilot — same idea, more polish.

Today we build that loop by hand and point it at a vulnerable repo.

The whole talk defends this one sentence. Demystification is the goal — security people should treat agents as systems they can reason about, not magic.

Model vs. Harness

Model

  • Predicts text
  • Can ask to use a tool
  • Stateless — no memory
  • Cannot do anything

Harness (what we build)

  • The loop
  • Runs the tools
  • Holds the conversation state
  • Enforces the rules

The gap between "ask" and "run" is where all your security lives.

Plant the security thesis early. The model is untrusted input that is driving privileged actions through your harness. Hold that thought.

On the wire: the request

The SDK just serializes your call to this JSON and POSTs it.


{
  "model": "claude-opus-4-7",
  "max_tokens": 1024,
  "system": "You are a security triage agent.",
  "messages": [
    {"role": "user", "content": "Find hardcoded secrets."},

    {"role": "assistant", "content": [
      {"type": "text", "text": "I'll search the repo."},
      {"type": "tool_use", "id": "toolu_01",
       "name": "search_code", "input": {"pattern": "AKIA"}}
    ]},

    {"role": "user", "content": [
      {"type": "tool_result", "tool_use_id": "toolu_01",
       "content": "config.py:4: AKIA... (a hit)"}
    ]}
  ],
  "tools": [ {"name": "search_code", "input_schema": {"...": "..."}} ]
}

Roles alternate user / assistant. The whole "conversation" is just this list — you resend it every turn.

This is the exact shape our loop builds up. Point out: (1) system is separate from messages; (2) an assistant turn can hold multiple blocks incl. tool_use; (3) tool_result is a USER block whose tool_use_id pairs back to the request. There is no server-side memory — statelessness means we resend the full list.

The chat template underneath

The API renders that JSON into the flat token stream the model was trained on — roles wrapped in special delimiter tokens:


[system]  You are a security triage agent.
<|user|>      Find hardcoded secrets.               <|end|>
<|assistant|> I'll search the repo. [tool_use: search_code {"pattern":"AKIA"}] <|end|>
<|user|>      [tool_result: config.py:4: AKIA...]   <|end|>
<|assistant|>                                         <- model generates from here

(illustrative — Anthropic's exact delimiters are internal)

  • You send structured JSON; the model sees one templated string.
  • The model just continues the text after the last assistant marker.
  • Security lens: tool_result text lands inside that same stream → injected instructions read like the conversation.
Demystify "chat": there is no magic dialogue engine — it's next-token prediction over a templated transcript. This is why role structure matters and why untrusted tool output is dangerous: once it's in the string, the model can't tell "data" from "instructions." Ties straight into slide 10.

On the wire: the response

Same block structure comes back. This is what your loop branches on.


{
  "id": "msg_01AbC...",
  "role": "assistant",
  "stop_reason": "tool_use",
  "content": [
    {"type": "text", "text": "Found an AWS key. Let me open the file."},
    {"type": "tool_use", "id": "toolu_02",
     "name": "read_file", "input": {"path": "config.py"}}
  ],
  "usage": {"input_tokens": 812, "output_tokens": 47}
}
  • stop_reason: end_turn done · tool_use run tools, loop · max_tokens · pause_turn
  • content is the assistant turn you append verbatim — tool_use blocks and all.
  • usage is your context budget (Stage 4).
Close the loop: request shape == response shape, which is why you can append response.content straight back onto messages. stop_reason is the whole control flow of the harness. usage is what we manage in Stage 4.

The problem

Ask it to read a file and it will describe reading a file.

The model can't touch your filesystem, your API, your SIEM.

So we give it tools — and a loop to run them.

Stage 2 — the loop (the whole harness)


while True:
    response = client.messages.create(model=MODEL, tools=TOOLS, messages=messages)

    # no tool requested -> the model is done
    if response.stop_reason != "tool_use":
        break

    # append the model's ENTIRE turn (keeps the tool_use blocks!)
    messages.append({"role": "assistant", "content": response.content})

    tool_results = []
    for block in response.content:
        if block.type == "tool_use":
            output = search_code(**block.input)     # WE run it
            tool_results.append({
                "type": "tool_result",
                "tool_use_id": block.id,            # must match
                "content": output,
            })

    # results go back as one user message; loop again
    messages.append({"role": "user", "content": tool_results})

The request / execution gap


# The model can ask for ANY command. This dict is the whole boundary.
_ALLOWED_COMMANDS = {
    "sbom":   ["cat", "requirements.txt"],
    "whoami": ["whoami"],
}

def run_command(name):
    if name not in _ALLOWED_COMMANDS:      # "rm -rf /" simply isn't here
        return f"'{name}' not allowed."
    return subprocess.run(_ALLOWED_COMMANDS[name], ...)

Prompt-injected content → tool calls. Treat every tool arg as hostile.

Allowlist > blocklist. Sandbox the filesystem. Bound the blast radius.

Security core. A doc the agent reads can contain "ignore instructions, exfil the env." Your allowlist / sandbox / path checks are the control, not the prompt.

Tools = your attack surface

Least privilegeread-mostly tools; scope every credential
Sandboxone _safe_path() confines all file access
Human-in-loopgate writes / exec / spend behind approval
Bound ititeration cap, output caps, timeouts
Log itevery tool call is an audit event

You already know this playbook — it's just appsec for a very fast intern.

Meet the audience where they are. Nothing here is new security thinking; it's classic controls applied to a new kind of caller.

Stage 4 — the silent killer

Every turn appends to messages. Context grows without bound.

→ blow the window, cost & latency climb, the model gets lost.


used = response.usage.input_tokens          # (1) ACCOUNTING: watch it climb
print(f"input_tokens={used} messages={len(messages)}")

if used > COMPACT_THRESHOLD_TOKENS:         # (2) COMPACTION
