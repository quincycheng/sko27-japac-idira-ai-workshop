Your Tasks

You can skip the first 2 steps if your terminal is already set up from Part 1.

1

Open a terminal

Press ⌘ + Space, type Terminal, press Return.

Press the Windows key, type PowerShell, press Enter. Use Windows PowerShell or PowerShell 7, not Command Prompt.

Check Claude Code is installed:

claude --version

You should see a version number.

“command not found”? Try this first. Your terminal cannot see the agent, which is a PATH problem rather than a missing install. The setup script sorts it out and tells you what it did:

cd ~/Downloads/sko27-japac-idira-ai-workshop
bash check-prereqs.sh
cd $HOME\Downloads\sko27-japac-idira-ai-workshop
.\check-prereqs.ps1

Then open a new terminal and try claude --version again. Still nothing? Raise your card.

2

Get your AWS credentials

Ask Idira for AWS credentials. Two commands, the same ones you ran in setup step 7. First log in:

idsec login

Sign in with your own CYBRWorld account. Then ask for the credentials. Use the Copy button:

eval "$(idsec exec sca cloud-access elevate --csp aws --workspace-id 409556437035 --roleIds arn:aws:iam::409556437035:role/CW-SCA-AdminAccess --raw | jq -r '.response.results[0].accessCredentials | fromjson | "export AWS_ACCESS_KEY_ID=\(.aws_access_key)\nexport AWS_SECRET_ACCESS_KEY=\(.aws_secret_access_key)\nexport AWS_SESSION_TOKEN=\(.aws_session_token)"')"
idsec exec sca cloud-access elevate --csp aws --workspace-id 409556437035 --roleIds arn:aws:iam::409556437035:role/CW-SCA-AdminAccess --raw | jq -r '.response.results[0].accessCredentials | fromjson | [.aws_access_key, .aws_secret_access_key, .aws_session_token] | @tsv' | ForEach-Object { $ak,$sk,$token = $_ -split "`t"; $env:AWS_ACCESS_KEY_ID=$ak; $env:AWS_SECRET_ACCESS_KEY=$sk; $env:AWS_SESSION_TOKEN=$token }

Nothing prints. That is success. Three environment variables now hold your credentials. Stuck? Setup step 7 covers every error this can give you.

💡 Notice what just happened. Nobody gave you a permanent AWS key. You asked for access, the platform checked who you are, and handed you credentials that expire. That is zero standing privileges.

⚠️ One terminal only. These values live in this window. Open a second tab and it will not know about them. If you close this window, run this step again.

3

Point Claude Code at Bedrock

Three more lines, in the same window. These tell the agent to use Claude on your company's AWS account instead of a public service:

export CLAUDE_CODE_USE_BEDROCK=1
export AWS_REGION=us-east-1
export ANTHROPIC_MODEL=us.anthropic.claude-opus-5
$env:CLAUDE_CODE_USE_BEDROCK=1
$env:AWS_REGION="us-east-1"
$env:ANTHROPIC_MODEL="us.anthropic.claude-opus-5"

Nothing prints. Step 5 proves these three worked.

Use the Copy button. The model name is long, and one wrong character produces a confusing error.

4

Go to the folder and switch on your virtual environment

Move into the workshop folder and activate the virtual environment you made during setup. This is a fresh window, so it is switched off:

cd ~/Downloads/sko27-japac-idira-ai-workshop
source .venv/bin/activate

Unzipped it somewhere else? Type cd (with the space), then drag the folder from Finder onto the terminal window. That fills in the path for you.

cd $HOME\Downloads\sko27-japac-idira-ai-workshop
.\.venv\Scripts\Activate.ps1

Unzipped it somewhere else? Open the folder in File Explorer, click the address bar, copy the path, and use that after cd.

Your prompt should now start with (.venv). Then move into the app itself:

cd sandbox-app
cd sandbox-app

Check you are in the right place. You should see summarize.py listed:

ls
dir

And check Python can find the library it needs:

python -c "import boto3; print('boto3 is ready')"

Any of this failing? Try this first. Almost always one of two things. Either there is no (.venv) in your prompt, in which case activate it and you are done. Or you never made one, in which case the setup script builds it and installs the libraries for you:

bash check-prereqs.sh
.\check-prereqs.ps1

Do not install anything globally to get past this. Raise your card if the script itself reports something it cannot fix.

5

Start the agent and say hello

claude

The terminal turns into a chat window. Now press Shift + Tab a few times. Watch the bottom line of the window and stop when it says auto. Went past it? Keep pressing Shift + Tab. It cycles round again.

In auto mode the agent runs commands without asking you first. Type this and press Return:

In one sentence, what does this app do?

It will read the files around you and answer. You are vibe coding. You did not open a single file yourself.

⚠️ Auto mode is for today. It is on so the room keeps pace. On Monday, in a repo that matters, do not use it. Read each command before you approve it.

Now leave the agent:

/exit

Pressing Ctrl + C twice does the same thing. You are back at your normal terminal prompt.

✅ You are ready when the agent gives you a sentence about summarising incident reports. If it does, wait here. Do not run ahead into Lesson 08 until the room is together.

Where Idira fits

🧨 The risk you just saw. The agent you just started holds your terminal's credentials and your file access. It inherited them from you.

What answers it

Secure Cloud Access
Issues the AWS credentials the agent inherits and expires them on a clock, not when somebody remembers to rotate a key.
Endpoint Privilege Manager
Decides which programs may start on a managed laptop, so "installed" and "allowed to run" stay two different answers.

Key takeaways

  • An agent is a program that inherited your access. Nobody granted Claude Code anything. It reads the same three AWS_* variables Idira gave you, and it can reach whatever you can reach.
  • Those credentials expire on their own. You asked for access, the platform checked who you are, and handed you something temporary. That is zero standing privileges, and you used it before anyone explained it.
  • One terminal window, one set of settings. A new tab knows none of this. It is the most common problem in the room today, and now you know the fix before you hit it.
  • Installed and allowed to run are different questions. If a managed laptop refuses to start the binary, that is endpoint application control working, not a broken install.
