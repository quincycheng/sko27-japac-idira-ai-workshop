## 03_context.py :: chat = session.Session(
### Two files and a cap, all on one call
until: max_tokens=600,
The agent's "personality" is `prompts/system.md`, read off disk and sent as text.
That is all a system prompt has ever been. You can open it, change it, and see the
answer change on the next turn.

`style=style` does the same job for the shape of the answer — `styles/eli5.md` or
`styles/deep-dive.md`, picked on the command line. Two files, both editable, both
charged for by the token, every single turn.

`max_tokens=600` caps the **reply**, not the conversation. When the window fills
up, Bedrock quietly shrinks it to whatever room is left: you will see `out=128` and
an answer that stops mid-sentence with `stop_reason=max_tokens`. That is the dumb
zone made visible — nothing failed, nothing warned you, the answer just got worse.

## 03_context.py :: for question in QUESTIONS:
### The script is allowed to hit the wall
until: break
Four questions in a row, on a model with an 8,192-token window, with the whole
transcript re-sent each time. `chat.send()` returns `None` when the request no
longer fits, and the loop simply stops.

Nothing here recovers. That is deliberate: the panel that just printed tells you
what your options are, and choosing between them — `/reset`, `/compact`, a shorter
style — is the skill this lesson is teaching.

## session.py :: parts = [p for p in (self.system_prompt, self.style_text) if p]
### Two files, one flat string
until: return "\n\n".join(parts)
The rules, the output style and anything in `memory.md` are joined into a single
blob of text and sent. By the time the model reads them there is no seam, no
precedence, and no label saying which of them came from where.

Everything a tool returns in lesson 04 lands in the same undivided stream. That is
not a bug in this app — it is how every model works, and it is why the only reliable
control in lesson 05 is the one that never reads this stream at all.

## session.py :: if instructions and not self.caps.system:
### When there is no system field at all
until: return history + [{"role": "user", "content": user_text}], None
Some models have no system role. For those, this branch glues the instructions onto
the front of your first message, because there is nowhere else to put them.

Same words, same tokens, same effect on the answer — and now visibly no boundary
between "our rules" and "the user's text". The `system` field on a modern model
hides this. It does not change it. Point `LEGACY_MODEL` at Mistral 7B (see
`config.py`) and you can watch this branch run.

## session.py :: if len(self.messages) <= 4:
### /compact, in four lines
until: head, middle, tail = self.messages[:1]
Keep the first message and the last two. Ask the model to summarise everything in
between. Replace the middle with that summary — and refuse to bother at all if
there is almost nothing there.

Note what survives: a summary is lossy, and whatever was in the middle is now gone
for good. Compaction is not free storage — it is choosing what to forget before the
window chooses for you.

## session.py :: candidate, dropped, note = middle, 0, ""
### Compacting at the wall costs you data
until: ui.note("Compact on the way up, not at the wall. This is why.")
Summarising takes a model call, and that call has to fit in the same window you are
trying to clear. At 98% full it does not — so this loop throws away the oldest half
of the transcript and tries again, **unread**, and says so out loud.

This is why a real harness compacts on the way up rather than waiting to fail. Try
it: `/fill 250`, then `/compact`, and watch it tell you what it discarded.
