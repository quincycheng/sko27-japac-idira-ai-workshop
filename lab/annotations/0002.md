## session.py :: history = list(self.messages) if self.remember else []
### The whole of "memory", and both places it is spliced in
until: instructions or None,
Memory is a Python list that the harness sends again, in full, on every single
turn. No database, no state on the model's side, nothing clever. With `remember`
false the same line sends an empty list — that was lesson 01.

Follow `history` down through both branches and notice they agree: whichever one
runs, what goes on the wire is `history + [your new message]`. The model does not
remember your conversation — it is **told** about it, from scratch, every time. If
something is not in this list, it did not happen.

(Why there are two branches at all is lesson 03's subject. Ignore it for now.)

## session.py :: def used(self) -> int:
### Why the bill climbs
until: return self.last_usage.input_tokens if self.last_usage else 0
`in=` on the footer is this number: the size of the request just sent. Not a
running total — how full the window was at the moment the model answered. Because
the transcript grows and is re-sent whole, the two climb together, and it never
comes back down.

Turn ten of a conversation re-sends turns one through nine. You pay for them again.
An agent that runs for an hour is paying for its own history, over and over, which
is the real reason long-running agents get slow and expensive — not the model
getting tired.
