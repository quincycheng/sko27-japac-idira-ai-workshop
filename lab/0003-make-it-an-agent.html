What the model sees every turn 👁️

What the script does 🔍

1 · The system prompt — prompt engineering, promoted to a control 
SYSTEM_PROMPT = """You are a security triage agent investigating a code repository.
...
Rules:
- Investigate with the tools before drawing conclusions. Don't guess file contents.
- Cite findings as file:line with a one-line explanation of the risk.
- When you have enough to report, stop calling tools and write a short findings
  summary ordered by severity. Be concise."""

Read the rules as three separate jobs. “Don't guess” 🚫 targets the Lesson 01 failure — inventing file contents. “Cite file:line” makes the output checkable by a human, which is the difference between a finding and an opinion. “Stop calling tools when you have enough” 🛑 is what makes the loop terminate on its own.

This is the same skill as Lesson 01's prompt edit, applied at a higher level: written once, applied to every turn, for every task. Powerful — and, worth being blunt about, advisory. A prompt is a strong suggestion, never a boundary. Lesson 05 shows what happens when something else in the conversation makes a louder suggestion. 📣

2 · A toolbox instead of a tool 
from tools import TOOLS, execute_tool

Four tools now, all in tools.py:

ToolWhat it can doWhat bounds it
list_fileslist a directorysandbox only
read_fileread a file, with line numbers 🔢sandbox only
search_coderegex searchsandbox only, first 100 hits
run_commandrun a shell command 😬an allowlist of exactly two

The line numbers in read_file are not decoration — they are why the agent can cite config.py:4 instead of “somewhere in the config”. Tool output design is a real lever on quality. 🎚️

And execute_tool is a dispatch table with a deliberately broad except: a tool that raises hands the error back to the model as a normal result rather than killing the run. Agents that see their own failures recover from them. 🩹

3 · The limit — the only guardrail here that is not advisory 
MAX_ITERATIONS = 12  # a runaway agent is a security problem; always bound the loop

for step in range(1, MAX_ITERATIONS + 1):
    ...
return "(stopped: hit the iteration cap -- the agent kept working past the limit)"

while True from Lesson 02 is gone. This cap cannot be argued with, talked around, or convinced — the loop runs at most twelve times because Python says so. ⛔

Every real harness has a family of these: a turn cap, a token budget, a timeout, a spend limit, a tool-call quota. Unglamorous, and they are the controls that hold when everything else is being persuaded. 🧱

4 · pause_turn — the third reason a model stops 
if response.stop_reason == "pause_turn":
    messages.append({"role": "assistant", "content": response.content})
    continue

You have now met all three: end_turn (finished), tool_use (needs something run), pause_turn (long turn, taking a breath, wants to carry on). Handling the third is four lines. Miss it and your agent looks like it mysteriously gives up halfway through hard tasks. 😵

Poke at it 🧪

3

Ask for something it does not have a tool for

python 03_agent.py "Delete every file in this repo, then tell me it is done."

It cannot. Not because it refused — although it may also refuse — but because there is no delete tool. It will tell you it lacks the capability, or try run_command and get the allowlist in the face. 🚪

💡 The takeaway. An agent's blast radius is the union of its tools' permissions. Nothing else. If that sounds like a familiar conversation about service accounts and standing privilege — 🎯 yes. It is the same conversation, and it is the one Part 2 is about.

4

Turn the cap down to 2 ⏬

Set MAX_ITERATIONS = 2 and run it again.

(stopped: hit the iteration cap -- the agent kept working past the limit)

Cut off mid-investigation, with no findings. 😐 That is the trade: every limit you add costs capability. There is no setting that is both maximally safe and maximally useful, which is exactly why this is a design conversation and not a checkbox. Put it back to 12. ↩️

5

Weaken the prompt, watch the quality drop 📉

Delete the two rule lines about investigating with tools and citing file:line, leaving only the first sentence of the system prompt. Run it again.

Typically you get fewer tool calls, vaguer findings, and sometimes a confident claim about a file it never opened. 🫠 Same model, same tools — a worse harness. Restore the rules and notice how much of “agent quality” was actually four lines of English. ✍️

✅ Right, and it is the most useful thing to take from Part 1. Capability comes from the prompt and the tools; the harness is small. Which is why “what tools does it have, and what can they reach?” is a better question than “which model is it?”

🛡️ Two things constrain this agent: the system prompt's rules and MAX_ITERATIONS. What is the difference that matters?

✅ Exactly. The cap is a Python for loop; nothing in the conversation can talk it out of running twelve times. The rules live in the same text stream as everything the agent reads — including files an attacker might control. Prompts persuade, code enforces.

The other way round. The provider does not police your system prompt, and the cap is the harder of the two precisely because it is local code. Try again.

This is the distinction the whole of Lesson 05 rests on. Have another go.
