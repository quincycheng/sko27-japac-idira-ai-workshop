The panel title shows the name of the LLM model: llama3-8b-instruct, not Claude. The line above the panel is the capability record, a list of what this model can do. Two entries matter:

  • tools=no: this model cannot call anything. Lesson 04 switches to a model that can.
  • window=8,192: the context window, the token budget for one request. Lesson 03 fills it.

Now the footer:

  • stop_reason=end_turn: the model finished talking. In Lesson 04 this value changes, and that change is the agent.
  • in= and out=: tokens sent and received. Watch in=. It grows with the conversation, and you pay for it.
  • The gauge: how much of the window this request used. Under one percent, for one question.
4

Ask a follow-up

The script drops you into a chatbox. Type exactly this:

Now say that again, but shorter.

The model has never seen your first question. It does not know what “that” means, because the first exchange was not sent with the second one.

Check the last line of the footer: history: dropped. Check in= too. It stays small however long you type, because nothing is kept.

/context

That shows everything the model is about to be sent: your last message, and nothing else. Type /help for the other commands. They use Claude Code's names, so you will reuse them in Part 2.

🧱 This is the wall, and there are two of them. This model cannot remember, and it cannot act. Ask it to read a file and it will invent an answer with full confidence. What is impressive about AI agents comes from the code around the model.

Knowledge Check

Three questions on what you just ran. Pick an answer to see why it is right or wrong.

You typed “Now say that again, but shorter.” and the model had no idea what “that” meant. Why?

Look at the gauge: a third of one percent. Nothing was pushed out, because nothing was in there. Try again.

A frontier model with a 200,000-token window fails the same way. This is not about model quality. Try again.

✅ Correct. The footer said so: history: dropped. Two separate requests, and the second did not include the first. Lesson 02 fixes that in code.

The capability line says window=8,192. What is that number?

It counts tokens, not messages, and it drops nothing. A token is roughly ¾ of a word. Try again.

✅ Correct. Your instructions, the conversation you resend, and the reply share the same 8,192 tokens. Go over it and you get an error.

That is max_tokens, a separate limit you choose. This script sets it to 400. Try again.

It answered “what is an agentic harness?” fluently and with total confidence. What does that tell you about whether the answer is correct?

Hedging is a writing style it can copy, not a signal. Ask it about a product that does not exist. Try again.

✅ Correct. Fluency is not evidence. Every answer is the most likely next text, and confident text is more likely than a hedge.

Frontier models hedge more honestly and still do the same thing. Never treat confidence as verification. Try again.

Key takeaways

  • A model call is one HTTPS request. Messages go up, one response comes back, the connection closes. Nothing is stored on the other side.
  • Forgetting is the default. The memory you are used to is code, written on your side of the request. That is Lesson 02.
  • An AI agent is an app. It runs as somebody, and reaches whatever that identity can reach.
  • So it is an identity problem. Nothing you ran needed a stored AWS key. Secure Cloud Access issued one that expires. Idira secures every identity involved: human, machine and now agentic AI.
