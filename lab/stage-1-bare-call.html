What the script actually does 🔍

Fifteen lines, four ideas. Open each one — they are short, and they are the vocabulary for the rest of the day.

1 · One line decides which AI you are talking to 
from config import MODEL, client

Every one of the five stages starts with this line and never mentions a vendor again. config.py is the only file that knows you are on Amazon Bedrock — swap it for Vertex, Gemini, or a model running on your own laptop and not one line of the harness changes.

🎤 Worth saying to a customer. “The model is a replaceable part.” It follows that your controls cannot live inside the model — they have to live in the code around it. That is the thread running through all five stages.

2 · The call itself 
response = client.messages.create(
    model=MODEL,
    max_tokens=1024,
    messages=[
        {"role": "user", "content": "In two sentences, what is an 'agentic harness'?"},
    ],
)

That is the whole API. You hand over a list of messages and get one reply. Note what is not there: no session, no user account, no memory. The model is a function — same input, similar output, and it forgets you instantly.

Which means every “conversation” you have ever had with a chatbot was the entire transcript being re-sent, every single turn. Hold on to that; it is why Stage 4 exists. 🧠

3 · Reading the answer — it is a list, not a string 
for block in response.content:
    if block.type == "text":
        print(block.text)

The reply arrives as content blocks. Today they are all text. From Stage 2 onward some of them are tool_use — the model asking for something to be run. Code that assumes content[0].text works right up until the model tries to use a tool, and then breaks.

4 · The three numbers at the bottom 
print(f"stop_reason : {response.stop_reason}")
print(f"input_tokens : {response.usage.input_tokens}")
print(f"output_tokens: {response.usage.output_tokens}")

stop_reason is why the model stopped talking. input_tokens is how much you sent it. That second number is the one that eventually kills a naive agent, because a growing conversation is re-sent in full every turn — Stage 4 watches it climb. 📈

Try it yourself 🧪

4

Prompt engineering, in one edit

Right now the prompt is a bare question. Open 01_bare_call.py in any text editor — or just ask Claude Code to do it for you — and replace the question with this:

You are briefing a security executive who has ten seconds.
What is an 'agentic harness'? Answer in exactly one sentence,
then name the single biggest risk it introduces.

Run it again. Same model, same code, same cost — a completely different answer. 🎯

That is prompt engineering: the only lever you have when a model call is all you have. A role, a constraint, a shape for the answer. It is genuinely powerful, and it is also where a lot of people stop — which is the problem, because…

5

Find the wall

Now try to get it to do something useful. Change the prompt to:

Read the file sandbox/config.py and tell me whether it contains
any hardcoded secrets.

Run it. 💥 It cannot. You will get a polite refusal, or — worse and much more instructive — a confident, entirely invented answer about a file it has never seen.

🧱 This is the wall. The model has no hands. It cannot read a file, run a command, or call an API. It can only produce text. Everything people find impressive or alarming about AI agents comes from the code we are about to write to get past this wall — not from the model.

🤖 The model gave a detailed answer about a file it could not read. Why?

There is no cache and no file access at all — the script sends one string and receives another. Try again.

✅ Exactly. Asked about a config file, the most plausible text is a config file's worth of findings. Fluency is not evidence. This is the single most useful thing to know about these systems.

Nothing was hidden — nothing was read. The script has no file tools in it whatsoever. Try again.

🔁 Why does every turn of a chat resend the whole conversation?

Billing follows from it, but it is not the reason. Look again at what the script sends and what it gets back. Try again.

Consistency is a happy result, not the cause. The real reason is more basic than that. Try again.

✅ Right. The model is stateless. “Memory” is a list that the code around it chooses to keep and resend — which makes memory a design decision, and a security one. Stage 4 is about exactly that.
