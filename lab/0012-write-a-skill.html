Write your own skill 📝

By the end of this lesson you will have written a skill that captures something only you know how to do, and watched a fresh agent pick it up without being told it exists. It is a text file, it is yours to keep, and it follows you into every project on your machine.

What a skill actually is: a folder with a SKILL.md file in it. That is the whole format.

.claude/skills/my-skill/SKILL.md

Inside there are a few lines of front matter, a name and a description, then prose. The description is the important part. It is how the agent decides whether this skill applies to what you just asked for. A vague description means a skill that never gets used.

⚠️ Not the same as a tool. A tool is a capability an MCP server gives the agent, something it can now do (Lesson 10). A skill is knowledge about how to do the job properly with capabilities it already has. You will hear these two used interchangeably in the wild. They are not the same, and a client who conflates them will design the wrong thing.

Broad or narrow? Start narrow. Both kinds work, and only one of them tells you when you got it wrong.

BroadNarrow
Teaches The shape of a thing, and how to discover the rest. One ordered procedure, start to finish.
Today's example skills/idsec/SKILL.md: “here is how this CLI is organised, use --help”. skills/zsp-aws/SKILL.md: “do these five things in this order”.
Fails by Being too vague to change the agent's behaviour at all. Being wrong in a way you notice immediately. Much better.

Open both of those files now, before you write anything. Two minutes of reading saves ten of guessing.

Your Tasks

Four steps. Step 3 is where the work is, because a good skill is an interview rather than a request. Tick each one off as you go.

1

Get a skill for writing skills

Inside the agent, open the plugin browser:

/plugin

Find mattpocock-skills in the marketplace and install it. Among other things it gives you writing-for-agents, a skill whose whole job is helping you write skills.

2

Pick something you actually know

The best skill is a procedure you have explained to a new colleague more than twice. Candidates from your real job:

  • How your team triages a phishing report
  • How you check whether a finding is a duplicate
  • The commands you always run when onboarding a new safe
  • How you assemble a customer health-check summary
  • Your naming and tagging conventions, so the agent stops inventing its own

💡 A Domain Consultant's version. “How I set up a customer demo tenant, in order, with the checks at each stage.” You do that repeatedly, the steps are exact, and the cost of getting step four wrong is an embarrassing demo. That is a perfect narrow skill.

3

Let it interview you

Do not ask it to write the skill. Ask it to interview you first. That is the difference between a skill that captures what you know and one that captures what the model guessed:

Using the writing-for-agents skill, help me write a skill that captures how my team does <the thing you do>. Interview me first, one question at a time, and do not guess at anything I have not told you.

Answer properly. The awkward questions, such as “what do you do when that check fails?”, are where the value is. That is the part you never write down.

4

Save it and test it cold

Save the result as .claude/skills/<name>/SKILL.md, the same layout you copied in Lesson 09.

Then the real test. Start a fresh conversation:

/exit
claude

Press Shift+Tab a few times until the bottom line says auto, then ask for the task in your own words, without mentioning the skill. If the description is good, the agent picks it up by itself. If it does not, the fix is almost always the description, not the body.

Key takeaways

  • A skill is a text file you wrote, and it is yours. Drop it in ~/.claude/skills/ and it follows you into every project on the machine.
  • The description is the matchmaker. If a fresh agent ignores your skill, rewrite the description in the words you would use, not the body.
  • Narrow first. A narrow skill fails loudly and specifically. A broad one fails by quietly changing nothing, which you will not notice for weeks.
  • Writing a skill is authoring privilege. It ends in commands running on a real machine, so whoever can edit that file can change what your agent does.
