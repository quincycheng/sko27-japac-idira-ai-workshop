Your Tasks

1

Start in an empty folder

The agent reads the folder it starts in, so a fresh folder means a blank slate.

mkdir ~/my-first-app
cd ~/my-first-app
claude
New-Item -ItemType Directory -Force $HOME\my-first-app | Out-Null
cd $HOME\my-first-app
claude

Press Shift+Tab a few times until the bottom line says auto.

🐍 About your virtual environment. The venv you made during setup belongs to the workshop folder. If what you build here needs a library, either make a new venv in this folder the same way, or ask the agent to do it. It knows how.

2

Ask for one small, genuinely useful thing

Pick something you would actually use, and keep it to one job. Good first asks, all from real security work:

  • “Write a Python script that reads a CSV of failed logins and prints the top 10 source IPs.”
  • “Write a script that takes a folder of log files and finds every line containing an email address.”
  • “Write a script that turns a list of CVE IDs into a summary table.”
  • “Write a script that checks a list of domains for an SPF record and flags the ones without one.”

Then run it. It will probably work. When it does not, paste the error back in and say “fix this”. That loop is the skill.

3

Run the experiment

Now the part that belongs in a security workshop. Ask for something that has to reach an external service, and say nothing at all about credentials:

Write a Python script that uploads a file to an S3 bucket.

Then look hard at what came back. Which did it do?

What it didWhat that means
Put a key straight in the fileYou have just recreated Lesson 08, by accident, in ten seconds.
Read an environment variableBetter. The secret still has to exist somewhere, but not here.
Used the default credential chainBest. This is what the elevated credentials from Lesson 09 give you, and it needs no secret at all.
Asked you what to doAlso good. Nothing wrong with an agent that checks.

⚠️ Compare with the person next to you. You will not always get the same answer from the same prompt. That, not any statistic, is the reason review is not optional. A control you cannot predict is a control you do not have.

4

Make it review itself

Finish with the habit worth taking to work:

Now review your own script for hardcoded secrets and insecure defaults. Be harsh.

Agents are much better at criticising code than at getting it right first time.

If your project is in git, /security-review does the same job with a proper security-focused prompt behind it. Try both.

Now leave the agent. Type /exit, or press Ctrl-C twice. You are back at your normal terminal prompt.

Knowledge Check

Pick an answer to see why it is right or wrong.

Two people run the same prompt and get different credential handling. Why does that matter?

Working and safe are different properties. The one with the key in it works perfectly, and that is the problem. Try again.

Better prompts help a lot, and you should write them. But they shift the odds rather than removing the variance. Try again.

✅ Correct. You cannot rely on a behaviour you cannot predict, so the check goes into the process. Generating faster makes that more important, not less.

🗣️ Ask your agent: “Which of the three credential approaches did you use, and what would you have to change to use the safest one?” Making it explain its own choice is how you learn to spot the choice next time.

Key takeaways

  • An empty folder and one sentence is now a working tool. The loop of run it, paste the error back, say “fix this” is most of the skill.
  • It made a credential decision you never asked for. Say nothing about secrets and something still gets chosen, sometimes a key in the file.
  • The same prompt gave the room different answers. A control you cannot predict is a control you do not have, which is why review is a step and not a hope.
  • Agents criticise code better than they write it. “Review your own script and be harsh” costs one sentence and is free accuracy.
