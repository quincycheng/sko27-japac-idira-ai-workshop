Optional advanced · Lesson 11

Build something from nothing with a simple prompt 🎸

Everything so far started from someone else's code. This is the bit that surprises people: an empty folder, one sentence, and a working tool.

  • Optional advanced
  • ⏱️ ~10 minutes
  •  

🧭 Nobody is expected to reach this page. The three optional lessons are alternatives, not a queue — start with whichever one you actually want. This one is the shortest, and the one most people enjoy most.

Steps

1

Start in an empty folder

Working somewhere new matters: the agent reads the folder it starts in, so a fresh folder means a blank slate with none of the sandbox app's baggage.

mkdir ~/my-first-app
cd ~/my-first-app
claude
New-Item -ItemType Directory -Force $HOME\my-first-app | Out-Null
cd $HOME\my-first-app
claude

🐍 About your virtual environment. The venv you made in the prework belongs to the workshop folder. If what you build here needs a library, either make a new venv in this folder the same way, or just ask the agent to — it knows how.

2

Ask for one small, genuinely useful thing

The trick is to pick something you would actually use, and to keep it to one job. Good first asks, all from real security work:

  • “Write a Python script that reads a CSV of failed logins and prints the top 10 source IPs.” 📊
  • “Write a script that takes a folder of log files and finds every line containing an email address.” 📨
  • “Write a script that turns a list of CVE IDs into a summary table.” 🐛
  • “Write a script that checks a list of domains for an SPF record and flags the ones without one.” 📮

Then run it. It will probably work. When it does not, paste the error back in and say “fix this” — that loop is the skill. 🔁

3

Run the experiment 🔬

Now the part that belongs in a security workshop. Ask for something that has to reach an external service, and say nothing at all about credentials:

Write a Python script that uploads a file to an S3 bucket.

Then look hard at what came back. Which did it do?

What it didWhat that means
🔑 Put a key straight in the fileYou have just recreated Lesson 07, by accident, in ten seconds.
🌱 Read an environment variableBetter. The secret still has to exist somewhere — but not here.
🎫 Used the default credential chainBest. This is what Lesson 09 left you with, and it needs no secret at all.
🙋 Asked you what to doAlso good. Nothing wrong with an agent that checks.

👥 Compare with the person next to you. You will not always get the same answer from the same prompt — and that, not any statistic, is the reason review is not optional. A control you cannot predict is a control you do not have.

4

Make it review itself

Finish with the habit worth taking to work:

Now review your own script for hardcoded secrets and insecure defaults.
Be harsh.

Agents are much better at criticising code than at getting it right first time. That asymmetry is free, and it costs you one sentence. 🪞

If your project is in git, /security-review does the same job with a proper security-focused prompt behind it. Try both.

🔬 Two people run the same prompt and get different credential handling. Why does that matter?

Working and safe are different properties. The one with the key in it works perfectly — that is the problem. Try again.

Better prompts help a lot, and you should write them. But they shift the odds rather than removing the variance. Try again.

✅ Exactly. You cannot rely on a behaviour you cannot predict, so the check goes into the process. Generating faster makes that more important, not less.

🗣️ Ask your agent: “Which of the three credential approaches did you use, and what would you have to change to use the safest one?” Making it explain its own choice is how you learn to spot the choice next time.
