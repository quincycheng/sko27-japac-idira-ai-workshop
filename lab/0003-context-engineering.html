Context engineering 🧠

2

Swap the output style, and watch it lose

Those answers ran 350 to 400 output tokens each. Switch to the short style. One line at a time:

/style eli5
What is a context window?

Watch what does not change. You will probably still get headings and bullets. styles/eli5.md forbids both. In rehearsal the answer was 366 output tokens, against deep-dive's 397. The file was read, sent and ignored.

Now clear the history and ask the same question:

/reset
What is a context window?

139 tokens. Plain prose, no headings. Same file, same model, same question. The only change is that three long bulleted answers are gone.

📣 History outweighs instructions. A style file is not a setting. It is text, competing with everything else in the window. Three examples of the opposite behaviour beat it. Note which way this cuts once the agent can read files. Instructions inside a file join the same competition, and they are more recent than yours.

3

Stand in the dumb zone

Talking your way to a full window takes about twenty turns. Let the app pad it instead:

/fill 60

The gauge goes amber around 58%. Now ask a real question, and read the answer critically:

Summarise everything we have discussed, then answer: what is a token?

The answer is usually vaguer, more repetitive, and it contradicts itself. Nothing announces that. No warning, no error, no stop_reason change.

🟠 About that 50% line. Amber at 50% and red at 80% are teaching devices, not published thresholds. What is real is on your screen: a filling window degrades answers silently. The filler is honest too. Every padded message says [workshop filler] in its own text, and the tokens it costs are real.

5

Compact, and get the answer you were refused

/compact

The harness keeps the first message and the last two. It asks the model to summarise the middle, then replaces the middle with that note. The gauge drops from 98% to about 10%. Ask the refused question again and it answers. Claude Code does the same thing when it prints compacting conversation…, with a better summary prompt.

⚠️ Compact on the way up, not at the wall. Summarising is itself a model call. It has to fit in the window you are trying to clear. Try it at 250%, one line at a time:

/fill 250
/compact

You get “Too full to summarise in one call. Dropped 8 messages unread.” At the wall, compaction is blind. A real harness compacts before it has to.

🔐 The security reading of compaction. Whatever the agent read, it keeps carrying: a credential in the transcript is in the summary too. The model chose what to keep, so the thing you are auditing rewrote your audit trail. Injected instructions survive the fold, and arrive on the other side as established fact.

Key takeaways

  • Prompts are text, and text can lose. Rules and styles are Markdown files competing with the transcript. Recent examples beat older instructions, so “we told it not to” is not a control.
  • The window fails twice. Silently first, with nothing on screen to say so, then loudly at the limit. Only the loud one raises an alert.
  • Compaction is a model call, so do it early. At the wall it drops messages unread, and the summary is written by the thing you are auditing.
  • Everything an agent reads, it carries. Secrets survive into summaries and are re-sent every turn. One more reason the agent should have nothing worth reading.
