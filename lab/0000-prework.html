The two-minute way ⚡

There is a script in the workshop folder that checks all seven items below, tells you which ones are missing, and asks before it fixes anything. Most people are done in a couple of minutes. Open a terminal, go to the workshop folder, and run it:

cd ~/Downloads/vibe-coding-workshop
bash check-prereqs.sh
cd $HOME\Downloads\vibe-coding-workshop
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\check-prereqs.ps1

🛑 About that middle line. Managed Windows laptops block scripts by default. That command allows them in this window only and needs no admin rights. Close the window and the setting is gone.

It prints a tick, a spanner or a cross for each item, then a summary and a numbered “still to do” list. Every offer is a [y/N] question — answer n and it changes nothing. 🤝

  • 🔍 Just look, change nothing: bash check-prereqs.sh --check-only .\check-prereqs.ps1 -CheckOnly
  • 🤖 Say yes to everything: bash check-prereqs.sh --yes .\check-prereqs.ps1 -Yes

🧾 Two promises the script keeps. Nothing is installed outside your home folder and this project folder, and nothing is changed without asking you first. It will also refuse to install Python — on a managed laptop that is the one step that needs admin rights, so it tells you to email us instead. 📧

Two things it cannot do for you: the idsec login check (step 6) and the AWS portal check (step 7, where it will remind you loudly).

Either route is fine. 🧑‍🏫 The manual steps below are the same work with the reasoning attached, so use them if the script will not run on your laptop, if a step fails, or if you would rather see what you are agreeing to before you agree to it. Nobody is checking which one you used.

1

Get the workshop folder onto your laptop

Use the link in your workshop email. It is either a zip to unzip or a repository to clone — your email says which. Either way, put it in Downloads. 📦

You should end up with a folder called vibe-coding-workshop containing lab, sandbox-app, ai-harness-app and skills.

📚 Why it is a repository. The folder is tracked by git, the tool developers use to keep a history of changes. You never have to use git today — but in Lesson 07 you will run Claude Code's built-in /security-review, and that expects to be looking at a project with a history. If you unzipped a zip, the history came with it. Nothing for you to do. ✅

You are reading this page from that folder, so if you can see this, step 1 is already done. ✅ There is no web server and no internet involved — these pages are just files.

Now open a terminal:

Press ⌘ Space, type Terminal, press Return.

Press the Windows key, type PowerShell, press Enter. Use Windows PowerShell or PowerShell 7 — not Command Prompt. Every command on this page is PowerShell.

Then move into the folder:

cd ~/Downloads/vibe-coding-workshop
cd $HOME\Downloads\vibe-coding-workshop

Stay in this folder for the rest of the prework. 📍

2

Check Python — and make python mean Python 3

python --version

You want 3.9 or newer. If you got a version number, skip to step 3. 🎉

If it said command not found, try:

python3 --version

If that works, you have Python — it is just called python3 on your machine. Rather than translating every command in this lab, add an alias so that python means python3 from now on:

echo 'alias python="python3"' >> ~/.zshrc
echo 'alias pip="pip3"' >> ~/.zshrc

Then close the terminal and open a new one, cd back to the workshop folder, and check again:

python --version

🔎 What that did. An alias is a nickname for a command, stored in your own shell settings file (~/.zshrc). It changes nothing about the installed Python and needs no admin rights — and it means every instruction in this lab that says python just works. If you use bash rather than zsh, use ~/.bashrc instead.

If it opened the Microsoft Store, or said the term is not recognised, try the Python launcher:

py --version

If that works, use py instead of python for the next step only. 👍 Once you have activated the virtual environment in step 3, the plain python command works everywhere — the environment supplies it. So this is a two-command inconvenience, not a whole-workshop one.

🔎 Prefer a permanent nickname? This adds an alias to your PowerShell profile, which is a file in your own user folder:

New-Item -ItemType File -Force $PROFILE | Out-Null
Add-Content $PROFILE 'Set-Alias python py'

Open a new PowerShell window afterwards. Entirely optional.

🆘 No Python at all? Reply to the workshop email — do not try to install it yourself, because on a managed laptop that is exactly the step that asks for admin rights. We will sort it out with you before the day.

3

Make a virtual environment 🐍

A virtual environment is a private folder holding this project's Python libraries. It is the standard way to work in Python, for three reasons that matter to you today:

  • 🧹 Nothing is installed system-wide, so nothing needs admin rights.
  • 🔒 The workshop cannot break some other tool on your laptop that also uses Python.
  • 🗑️ Cleaning up afterwards is deleting one folder.

From inside the vibe-coding-workshop folder, create it:

python -m venv .venv

Then activate it:

source .venv/bin/activate
py -m venv .venv

Then activate it:

.\.venv\Scripts\Activate.ps1

🛑 “running scripts is disabled on this system”? Common on managed Windows laptops, and no admin rights needed to work around it. This allows scripts for this window only, then activates:

Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1

If you would rather not repeat that in every window, -Scope CurrentUser -ExecutionPolicy RemoteSigned makes it stick for your account only.

Your prompt now starts with (.venv). That is how you know it is on. 👀

Install what the two apps need — the sandbox app you will fix in Part 2, and the harness lessons you will build in Part 1:

pip install -r sandbox-app/requirements.txt
pip install -r ai-harness-app/requirements.txt

And check them both:

python -c "import boto3, anthropic; print('libraries ready')"

Two small libraries, about a minute. Neither needs admin rights — they land inside .venv. 🪶

📌 The one thing to remember from this page. A virtual environment is per terminal window. Open a new window and the (.venv) is gone, and Python will not find boto3. The fix is always the same — cd to the workshop folder and activate again:

cd ~/Downloads/vibe-coding-workshop
source .venv/bin/activate
cd $HOME\Downloads\vibe-coding-workshop
.\.venv\Scripts\Activate.ps1

This is the single most common problem on the day. It is also the easiest to fix — now you know. 💪

5

Install the idsec CLI

idsec is Idira's command-line tool. It is a single file — there is no installer, and nothing is registered with your operating system.

Download the archive for your machine from the official releases page:

🔗 github.com/cyberark/idsec-cli-golang/releases

Take the newest release and pick the file matching your machine:

MachineLook for a file name containing
🍎 Mac with Apple silicon (M1–M4)darwin and arm64
🍎 Mac with an Intel chipdarwin and amd64
🪟 Windowswindows and amd64

Not sure which Mac you have? Run uname -m — arm64 means Apple silicon, x86_64 means Intel. Switch this page to 🍎 macOS if you are on a Mac.

📛 The file inside is not called idsec. The archive names the program after the platform it was built for, so on a Mac you get idsec-darwin and on Windows you get idsec-windows.exe, next to a licence and a readme. Every command in this guide says idsec, so the install below renames it. That rename is the only fiddly part of this step, and it is why the commands look longer than a one-liner.

Make a folder for personal tools, unpack just the program into it under the name the rest of the guide uses, and tell your shell where to look:

mkdir -p ~/bin
tar -xzf ~/Downloads/idsec_*.tar.gz -C ~/bin idsec-darwin
mv ~/bin/idsec-darwin ~/bin/idsec
chmod +x ~/bin/idsec
echo 'export PATH="$HOME/bin:$PATH"' >> ~/.zshrc

If you downloaded more than one archive while working out which Mac you have, put the exact file name in place of idsec_*.tar.gz so it is unambiguous.

Close the terminal, open a new one, then check:

idsec version

If macOS refuses to run it (“cannot be opened because the developer cannot be verified”), run xattr -d com.apple.quarantine ~/bin/idsec and try again.

Make a folder for personal tools, unpack just the program into it under the name the rest of the guide uses, and add that folder to your own PATH. This is the user-level setting, so no admin rights are needed:

New-Item -ItemType Directory -Force $HOME\bin | Out-Null
$archive = (Get-ChildItem $HOME\Downloads\idsec_*windows*.tar.gz)[0].FullName
tar -xzf $archive -C $HOME\bin idsec-windows.exe
Move-Item $HOME\bin\idsec-windows.exe $HOME\bin\idsec.exe -Force
$user = [Environment]::GetEnvironmentVariable("Path", "User")
[Environment]::SetEnvironmentVariable("Path", "$user;$HOME\bin", "User")

The second line finds the archive you downloaded so you do not have to type a version number. Then close PowerShell and open a new window, because the PATH change only applies to new windows, and check:

idsec version

If Windows blocks the file, right-click $HOME\bin\idsec.exe → Properties → tick Unblock → OK.

🖥️ Blocked by your company's endpoint policy? If it refuses to run and the message mentions a policy, an administrator, or Idira Endpoint Privilege Manager, that is application control doing its job — deciding which programs are allowed to run on a managed laptop. Please don't try to work around it. If you are offered a Request authorization button, use it; otherwise reply to the workshop email today and we will get idsec allowed for you. ✋

Worth noticing rather than resenting: it is the same idea as the rest of the day, one layer lower down. 🙂 Lesson 08 comes back to it.

6

Set up your idsec profile and log in

idsec configure

It asks a few questions. Answer them using the values printed in your workshop email — your tenant subdomain and username. Where a question shows a default in brackets, press ReturnEnter to accept it.

Then log in:

idsec login

Follow the prompts. On most tenants the sign-in happens in the terminal: it asks for your password, then for a multi-factor check if your tenant requires one. On some it opens a browser window instead — if that happens, sign in there and come back. Either way you end up with a success message in the terminal. ✅

🔑 Which password? The one from your workshop email — the same login you use for the portal. Nothing is echoed as you type it, which is normal.

Once only. Do this now and then leave it alone. On the day you will only need idsec login. Running idsec configure a second time overwrites your settings, and that is a five-minute detour in a session with about fifty minutes of hands-on time.

This is the one step where a problem is invisible until the session starts, so please actually click through it. 🙏

  1. Open https://ngid.cyberark.cloud/

  6. Next to it you should see Access keys (or Get credentials). Click it and confirm you get a dialog with tabs and an Option 1: Set AWS environment variables section

You do not need to copy anything yet. You just need to know the link is there. 👀
